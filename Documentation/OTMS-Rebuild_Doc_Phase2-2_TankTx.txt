Core calculation chain (utils_calc.py)
-------------------------------------
Interpolation:
• tank_volume_from_dip_cm(sess, tank_name, dip_cm) → TOV (bbl)
• free_water_from_water_cm(sess, tank_name, water_cm) → FW (bbl)
• GOV = max(TOV - FW, 0)

API @60°F (two routes):
• api60_from_api_obs(api_obs, sample_temp, unit)  → uses api_observed_to_api60(...)
• api60_from_density_obs(density_obs, sample_temp, unit) → uses density_obs_to_api60(...)
(Compatibility functions ensure older calls still work.)

VCF:
• vcf_from_api60_and_tank_temp(api60, tank_temp, unit) → calls calculate_vcf(...)
• calculate_vcf(api60, temp_f): alpha = 341.0957 / rho60²; vcf = exp(-alpha ΔT − 0.8 α² ΔT²)

Volumes:
• gsv_from_gov_vcf(GOV, VCF) → GSV (rounded 0 dp)
• bsw_volume_from_gsv_pct(GSV, BSW%) → BSW volume
• nsv_from_gsv_bsw(GSV, BSW_bbl) → NSV (rounded, clamped ≥ 0)
(Convenience: nsv_from_gsv_bsw_pct(GSV, BSW%) if enabled)

LT / MT:
• get_lt_factor(sess, api60) → interpolate Table 11
• lt_from_nsv_api(sess, NSV, api60) → (LT, lt_factor)
• mt_from_lt(LT) and mass_lt_from_mt(MT)
• mass_mt_from_gsv_api60(GSV, api60) → direct MT (via Table 11 then 1.01605)

Small converters:
• density_from_api(api) and api_from_density(density)
• normalize_temp_unit(), c_to_f(), f_to_c(), bounded_temp()

Recommended plan (my POV)
-------------------------
Given your intent to finish **all entry tabs** first, we’ll do it in this order to maximize reuse and minimize regression:
A) Finalize Tank Entry tab (WRITE path + audit + delete approval + PDF)
   • Save flow (ORM write), edit flow (row-by-row updates), guarded delete flow with approval & audit
   • Standardized PDF print: “Daily Tank Entry” (A4 portrait, 0.5 cm margins) + CSV/XLSX
   • Unit tests: calculation drift checks (spot values), validation ranges, negative clamps

B) Implement Meter Records tab (Entry UX + calculations if any + write path + audit + PDF)
   • Reuse tank selectors + calibration where relevant
   • Common components: date pickers, glass buttons, export

C) Implement Condensate Records tab (Entry UX + write path + audit + PDF)
   • Leverage common validators; reuse GSV/VCF pipeline if applicable

D) Implement Produced Water Records tab (Entry UX + write path + audit + PDF)
   • Separate validation (may not need API/VCF; mostly volumes + disposal/export references)

E) Implement Production tab (Entry UX + write path + audit + summary cards + PDF)
   • Per-location behavior hooks where the logic diverges (e.g., Beneku nuances)
   • Common reporting blocks and exports

F) Only after (A–E): Build **View Transactions (All)** page
   • Single viewer with tabs: Tank / Meter / Condensate / Produced Water / Production
   • Shared date range header + unified export bar (CSV/XLSX/PDF)
   • Consistent column conventions; audit on queries

Why this order?
• It keeps the data model and write-paths stable before we build the “single pane of glass” viewer.
• It avoids reworking the viewer multiple times as schemas firm up from each entry tab.
• It ensures the audit trail is complete from day one for every type of entry.

Appendix — Common validation ranges (suggested)
-----------------------------------------------
• Dip/Water: 0–(tank reference height) cm (use tank’s calibration bounds if available)
• Sample Temp: °C 0–60, °F 32–120 (bounded_temp())
• Tank Temp: °C 0–60, °F 32–120 (bounded_temp())
• API Obs: > 0 (prefer 8–50 typical range)
• Density Obs: > 0 (typical 650–1050 kg/m³)
• BS&W %: 0–100 (bounded and integer rounding for volumes)
