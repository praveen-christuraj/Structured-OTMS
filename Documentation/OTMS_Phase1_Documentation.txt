3) APPLICATION FLOW (HIGH-LEVEL)
--------------------------------------------------------
1. main_app.py boots:
   - init_db() ensures tables exist.
   - ensure_default_admin_user() seeds the first admin if there are no users (username=admin, password=Admin@123, role=admin-operations).
   - Session defaults are created.

2. If NOT logged in:
   - Only the Login page is shown (app_pages/login.py).
   - Successful login stores user dict in st.session_state["auth_user"].
   - Audit entries are recorded for login (success/failure).

3. If logged in:
   - Session timeout check runs:
     * Timeout: 30 minutes of inactivity (SecurityManager.SESSION_TIMEOUT_MINUTES = 30).
     * When <5 minutes remaining, a sidebar warning is shown.
     * If expired: log SESSION_EXPIRED, clear session, show Login.
   - Last activity timestamp is refreshed in DB and in session (sliding timeout).
   - Sidebar pages are computed with get_pages(user, active_location_id):
     * Role-based: uses PermissionManager (Phase 1 pages: Home/My Tasks for all; Manage Locations/Users/Audit Log only for admin roles).
     * Location-aware: hooks are present to read per-location visibility flags (for Phase 2/3 operational pages).
   - Single-click navigation updates st.session_state["current_page"] and calls st.rerun().

4. Pages (Phase 1):
   - Home: location selector + summary (DashboardMetrics). Non-admins are locked to their assigned location; admins can switch.
   - My Tasks: list & act on tasks assigned to user (TaskManager).
   - Manage Locations: create & list locations; audit CREATE.
   - Manage Users: create, edit role/location/name, reset password, toggle active, reset 2FA, delete; audits for all actions.
   - Audit Log: filter & view audit entries (admin-operations/admin-it/manager).

(When operational pages are added in later phases, PermissionManager.can_access_operational_pages(user) + Location Settings will also be applied.)

5) LOCATION-AWARE BEHAVIOR
--------------------------------------------------------
- On login, st.session_state["active_location_id"] defaults to the user’s assigned location_id when present.
- Home page behavior:
  * Admins (admin-operations, admin-it): can choose any location from the selector.
  * Non-admins with assigned location: selector is locked to their assigned location.
  * Non-admins without assigned location: free selection (admin must assign later).
- Location Settings (Phase 2/3):
  * location_config.get_location_page_visibility(session, location_id) returns a dict of visibility flags:
    - show_tank_transactions
    - show_yade_transactions
    - show_fso_operations
    - show_reports
  * get_pages(user, active_location_id) reads these flags to populate sidebar with operational pages (when those pages exist).


--------------------------------------------------------
6) SESSION TIMEOUT (30 MIN) & WARNINGS
--------------------------------------------------------
- SecurityManager.SESSION_TIMEOUT_MINUTES = 30 (set in main_app.py).
- SecurityManager.is_session_expired(user_dict) checks session inactivity.
- When time left < 5 minutes:
  * Sidebar shows: “Session expires in ~N minute(s). Any activity will keep you logged in.”
- On expiration:
  * Audit: action=SESSION_EXPIRED, resource_type=User, success=False
  * App clears auth_user, active_location_id, current_page, logout_confirm, and shows Login again.
- Each request (rerun), the app updates last_activity:
  * DB: SecurityManager.update_last_activity(session, user_id)
  * Session: user["last_activity"] = datetime.utcnow().isoformat()


--------------------------------------------------------
7) AUDIT LOGGING (WHAT GETS LOGGED IN PHASE 1)
--------------------------------------------------------
- Login success/failure (AuthManager.authenticate → SecurityManager.log_audit)
- Logout (sidebar button with confirmation)
- Session expired (main_app checks; logs SESSION_EXPIRED)
- Manage Locations (CREATE)
- Manage Users (CREATE, UPDATE details, PASSWORD_RESET, ACTIVATE, DEACTIVATE, 2FA_RESET, DELETE)
- Tasks (status changes) via TaskManager.update_status (APPROVED/REJECTED/COMPLETED)

Audit fields typically include:
- timestamp, username, action, resource_type, resource_id, location_id, details, ip_address, success
